# Penetration Test Report: Hack The Box - Vaccine

## Executive Summary

This report details the penetration test of the "Vaccine" machine on the Hack The Box platform. The assessment identified a vulnerable web application parameter susceptible to SQL Injection. This vulnerability was leveraged to extract database credentials and execute arbitrary operating system commands, leading to initial access. Subsequent enumeration revealed a misconfigured `sudo` permission on the `vi` text editor, allowing for local privilege escalation to the root user.

## Reconnaissance & Enumeration

The engagement began with enumerating the target web server, which hosted a MegaCorp Car Catalogue dashboard. During initial discovery, a locked archive file named `backup.zip` was identified and downloaded to the local attack machine.

To access the archive, the password hash was extracted and subjected to an offline dictionary attack.

* **Extracting the Hash:** The `zip2john` utility was used to isolate the mathematical hash from the zip file.
* **Password Cracking:** John the Ripper was executed using the `rockyou.txt` wordlist to brute-force the extracted hash, successfully revealing the plain-text password.
* **File Extraction:** The archive contained source code files, including `index.php` and `style.css`, indicating the backend infrastructure of the web application.

## Initial Access via SQL Injection

Analysis of the Car Catalogue dashboard revealed a search function. Using browser developer tools, the raw HTTP GET request generated by the search parameter (`?search=`) was captured and saved to a local text file (`req.txt`) for automated vulnerability testing.

The automated SQL injection tool, `sqlmap`, was deployed against the saved request, confirming that the backend PostgreSQL database was vulnerable to Boolean-based and time-based blind SQL injection.

**Database Enumeration**
The following commands were executed to map the database structure and extract credentials:

1. `sqlmap -r req.txt --batch --dbs` (Identified the `public` database).
2. `sqlmap -r req.txt --batch -D public --tables` (Identified the `users` table).
3. `sqlmap -r req.txt --batch -D public -T users --dump` (Extracted the database usernames and password hashes).

**Gaining a Reverse Shell**
With administrative database access confirmed, `sqlmap`'s `os-shell` feature was utilized to force the database to execute underlying operating system commands via the PostgreSQL `COPY ... FROM PROGRAM` function. A Netcat listener was established on the attack machine, and a reverse shell payload was executed to establish an interactive session as the `postgres` user.

To stabilize the session and prevent accidental termination, the shell was upgraded using Python:
`python3 -c 'import pty;pty.spawn("/bin/bash")'`

At this stage, initial access was secured, and the `user.txt` flag was captured.

## Privilege Escalation

With a stable foothold as the `postgres` service account, local enumeration was conducted to identify privilege escalation vectors.

Running the command `sudo -l` revealed that the current user was explicitly permitted to execute the `vi` text editor as the `root` user without requiring a password.

Because text editors often contain built-in features to execute shell commands, this misconfiguration was exploited using a well-documented GTFOBins bypass technique:

1. The `vi` editor was launched with elevated privileges: `sudo vi /etc/postgresql/11/main/pg_hba.conf`
2. Command Mode was initiated by pressing the `:` key.
3. The editor's shell variable was explicitly set to the system shell: `set shell=/bin/sh`
4. A new shell process was spawned from within the editor: `:shell`

This effectively forced the `vi` application to hand over a new terminal session running with its own elevated permissions. The shell spawned as `root`, completing the full compromise of the target and allowing for the retrieval of the `root.txt` flag.
